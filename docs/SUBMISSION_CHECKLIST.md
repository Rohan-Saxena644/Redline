# PayPal AI Hackathon submission checklist

Checked against the [official rules](https://paypalaihackathon.devpost.com/rules), [overview requirements](https://paypalaihackathon.devpost.com/) and [resources](https://paypalaihackathon.devpost.com/resources) on **2026-11-05**. Recheck the live form/rules before submission. No submission has been made.

The posted deadline is **November 12, 2026, 12:00 PM PST**, which is **November 13, 2026, 1:30 AM IST**. Eligibility, sanctions/exclusions and team authority must be assessed by the entrant against the full rules. This checklist is a practical preparation aid.

- [ ] Register/join with an eligible Devpost account; confirm team representative authority.
- [ ] Verify meaningful PayPal **sandbox** integration and meaningful AI use with actual configured model evidence. Implemented adapters alone are not live proof.
- [x] Provide runnable source and complete local setup instructions. Fixture and simulated provenance are explicit.
- [ ] Finish real model mission → PayPal order creation → buyer approval → server capture; inspect the actual completed capture receipt.
- [ ] If claiming webhook delivery, demonstrate signature verification, duplicate delivery and authoritative reconciliation in an authorized reachable environment.
- [ ] Publish source to a public GitHub, GitLab or Bitbucket repository **only after separate authorization**. Include all necessary code/assets/setup and a detectable top-level MIT license.
- [ ] Provide a functional demo accessible to judges through complete repository setup instructions **or** an actual hosted demo. A static mockup is insufficient; hosting is not mandatory.
- [ ] Record a functioning-device video **under 3 minutes**, upload publicly to YouTube after authorization, and supply its actual link. Remove credentials, personal payment details and unlicensed music/material.
- [ ] Explain features, actual model/tool usage, PayPal's role, limitations and progress during the submission period in the text description. Existing projects must describe meaningful new work.
- [ ] Confirm authorization and license/terms for each third-party integration or asset. Sponsor tools are optional; check additional terms if seeking sponsor-specific prizes.
- [ ] Review judging dimensions: implementation, coherent design, specific impact, idea differentiation and clear functioning demonstration. Do not invent novelty, benchmarks, audits or saved-revenue claims.
- [ ] Enter all required form fields and exact repository/video/demo links, accept rules as appropriate, and submit before the deadline **only after separate authorization**.
- [ ] Generate the local source/version manifest from a clean reviewed commit, then commit that metadata separately; see `SUBMISSION_FREEZE.md`.
- [ ] Resolve the access risks in `ACCESS_CONTINUITY.md`, especially currently unestablished zero-spend real-model access. Keep required accounts/quotas/credentials usable through the actual December announcement.
- [ ] After submission, preserve the exact repository commit, video and linked materials unchanged through the announcement; operational access maintenance does not authorize behavior/material changes.

Production money, paid resources/subscriptions, public deployment, package publication, repository publication and hackathon submission were not authorized as part of implementation. Manual credential configuration, eligibility review, actual live verification, recording and publication/submission remain entrant steps.
